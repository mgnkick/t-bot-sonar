# t-bot-sonar

Telegram-бот с командами `/start`, `/go`, `/buzz`, `/help`, `/recommend` и `/app` работает как воронка из канала на сайт и к скачиванию приложения. В 08:00 UTC+3 он публикует дайджест из четырёх-пяти популярных материалов о сетях; в 13:00 — короткий практический совет; в 18:00 — пошаговый разбор типичной проблемы подключения. Утренние истории берутся из Hacker News Top/Best/Show/Ask/New и тематических RSS Lobsters за последнюю неделю, с расширенными терминами по телекоммуникациям, широкополосному доступу, Wi‑Fi и интернет-инфраструктуре. Заголовок каждой новости ведёт на первоисточник. В дайджесте есть русская выжимка, причина популярности, контекст для читателя и уместная ссылка на `FREEDOM_URL`.

Все кнопки и призывы из Telegram ведут сначала на практические страницы сайта `/guides/`, `/guides/signal/`, `/guides/channels/` или `/guides/diagnostics/`. На этих страницах есть инструкция и кнопка APK. UTM-метки перехода из Telegram автоматически переносятся на скачивание, чтобы различать кампании и форматы в access-логах сервера. Запрос APK не подтверждает установку; для подсчёта первых запусков понадобится добровольная, прозрачно описанная аналитика внутри приложения. Повторные новости отсеиваются в течение двух дней.

Заголовки и описания переводятся на русский локальной LibreTranslate. Отбор использует контекстные термины, чтобы охватить телеком- и интернет-инфраструктуру без включения историй только о социальных или нейронных сетях. Для публикаций Telegram бот должен быть администратором канала с правом публикации сообщений. Установщик использует long polling, поэтому входящий порт на сервере открывать не нужно.

В личном чате `/recommend [технология или регион]` выдаёт пример и ссылку на `freedom1.ru`. Запрос о провайдере в Краснодарском крае, Адыгее, Башкортостане или Челябинской области автоматически получает ссылку на проверку покрытия и тарифов. Бот оговаривает, что покрытие зависит от точного адреса. `/subscribe` и кнопка в приветствии ведут в `@wifisonar`, чтобы читатель сам подписался на новости; бот не импортирует адресную книгу и не пишет людям первым.

Команда `/app` и кнопки в подборках ведут прямо на APK. Ссылки помечаются UTM-метками для утреннего/вечернего выпуска, каждой статьи и основных команд бота. Это позволяет учитывать переходы и запросы на скачивание в логах сайта; без изменений в самом приложении эти метки не подтверждают завершённую установку.

## Запуск на Ubuntu через systemd

1. Создайте бота у `@BotFather` через `/newbot` и получите токен.
2. Создайте `/etc/t-bot-sonar.env` с переменными `BOT_TOKEN=...`, `SITE_URL=https://179.253.79.218/`, `FREEDOM_URL=https://freedom1.ru/` и `CHANNEL_ID=@wifisonar`, затем ограничьте доступ: `chmod 600 /etc/t-bot-sonar.env`.
3. Создайте системного пользователя `tbot`, скопируйте `t-bot-sonar.service` в `/etc/systemd/system/` и выполните `systemctl daemon-reload`, `systemctl enable --now t-bot-sonar`.
4. Проверьте журнал: `journalctl -u t-bot-sonar -f`, затем отправьте боту `/start`.

Для обновления кода: `git pull` в папке проекта и `systemctl restart t-bot-sonar`. Не коммитьте секретный файл и не публикуйте токен.

## Локальный переводчик

На сервере с Docker запустите локальный переводчик, доступный только с самого сервера:

```sh
docker run -d --name t-bot-translate --restart unless-stopped \
  --memory=768m --cpus=1 -p 127.0.0.1:5000:5000 \
  libretranslate/libretranslate:latest \
  --host 0.0.0.0 --load-only en,ru --threads 1 --req-limit 30
```

Проверьте готовность: `curl http://127.0.0.1:5000/health`. Переводчик не требует API-ключа, а тексты остаются на сервере.

Содержание практических постов меняется в `DAY_TIPS` и `EVENING_EXPLAINERS` в `bot.py`. Расписание меняется в `SCHEDULE`. Страницы сайта находятся в `web/guides/`; для выкладки на сервер используйте `scripts/deploy-guides.sh`.
