# t-bot-sonar

Telegram-бот с командами `/start`, `/go`, `/buzz`, `/help`, `/recommend`, `/app` и `/donate` работает как воронка из канала на сайт и к скачиванию приложения. В 08:00 UTC+3 он публикует дайджест из четырёх-пяти популярных материалов о сетях; в 13:00 — короткий практический совет; в 18:00 — пошаговый разбор типичной проблемы подключения. Утренние истории берутся из Hacker News Top/Best/Show/Ask/New и тематических RSS Lobsters за последнюю неделю, с расширенными терминами по телекоммуникациям, широкополосному доступу, Wi‑Fi и интернет-инфраструктуре. Заголовок каждой новости ведёт на первоисточник. В дайджесте есть русская выжимка, причина популярности, контекст для читателя и уместная ссылка на `FREEDOM_URL`.

Кнопка «Сайт приложения» ведёт на главную страницу сайта. Практические материалы по-прежнему доступны из дайджеста и публикаций. UTM-метки перехода из Telegram автоматически переносятся на скачивание, чтобы различать кампании и форматы в access-логах сервера. Запрос APK не подтверждает установку; для подсчёта первых запусков понадобится добровольная, прозрачно описанная аналитика внутри приложения. Повторные новости отсеиваются в течение двух дней.

Заголовки и описания переводятся на русский локальной LibreTranslate. Отбор использует контекстные термины, чтобы охватить телеком- и интернет-инфраструктуру без включения историй только о социальных или нейронных сетях. Для публикаций Telegram бот должен быть администратором канала с правом публикации сообщений. Установщик использует long polling, поэтому входящий порт на сервере открывать не нужно.

В личном чате `/recommend [технология или регион]` выдаёт пример и ссылку на `freedom1.ru`. Запрос о провайдере в Краснодарском крае, Адыгее, Башкортостане или Челябинской области автоматически получает ссылку на проверку покрытия и тарифов. Бот оговаривает, что покрытие зависит от точного адреса. `/subscribe` и кнопка в приветствии ведут в `@wifisonar`, чтобы читатель сам подписался на новости; бот не импортирует адресную книгу и не пишет людям первым.

Команда `/app` и кнопки ведут на сайт приложения. Ссылки сайта помечаются UTM-метками для выпусков и основных команд бота. Это позволяет учитывать переходы и запросы на скачивание в логах сайта; без изменений в самом приложении эти метки не подтверждают завершённую установку.


## Поддержка проекта

В меню бота и команде `/donate` доступен сценарий поддержки WiFi Sonar. Пользователь выбирает криптовалюту (BTC, ETH или RVN) либо перевод в рублях на карту Сбера. Платёжные данные читаются из переменных окружения и не хранятся в Git.

Добавьте в защищённый файл окружения только те реквизиты, которые готовы показывать публично:

- `DONATE_BTC_ADDRESS` — адрес Bitcoin;
- `DONATE_ETH_ADDRESS` — адрес Ethereum;
- `DONATE_RVN_ADDRESS` — адрес Ravencoin;
- `DONATE_SBER_CARD` — номер карты Сбера для перевода в RUB;
- `DONATE_SBER_RECIPIENT` — необязательное имя получателя.

Пустое значение скрывает соответствующий способ оплаты. BTC, RVN и карта Сбера уже совпадают с публичной карточкой поддержки сайта. ETH включается только при корректном адресе формата `0x` + 40 шестнадцатеричных символов. Проверенный адрес ETH добавлен в конфигурацию бота. После изменения env-файла перезапустите службу бота. Перед запуском проверьте каждый адрес и сеть: отправка в неправильную сеть может привести к потере средств. Не помещайте реальные реквизиты в `env.example`, коммиты или публичные issue.

## Запуск на Ubuntu через systemd

1. Создайте бота у `@BotFather` через `/newbot` и получите токен.
2. Создайте `/etc/t-bot-sonar.env` с переменными `BOT_TOKEN=...`, `FREEDOM_URL=https://freedom1.ru/` и `CHANNEL_ID=@wifisonar` и заполните нужные `DONATE_*` реквизиты, затем ограничьте доступ: `chmod 600 /etc/t-bot-sonar.env`.
3. Создайте системного пользователя `tbot`, скопируйте `t-bot-sonar.service` в `/etc/systemd/system/` и выполните `systemctl daemon-reload`, `systemctl enable --now t-bot-sonar`.
4. Проверьте журнал: `journalctl -u t-bot-sonar -f`, затем отправьте боту `/start`.

Для обновления кода: `git pull` в папке проекта и `systemctl restart t-bot-sonar`. Не коммитьте секретный файл и не публикуйте токен.

## Локальный переводчик

На сервере с Docker запустите локальный переводчик, доступный только с самого сервера:

```sh
docker run -d --name t-bot-translate --restart unless-stopped \
  --memory=768m --cpus=1 -p 127.0.0.1:5000:5000 \
  libretranslate/libretranslate:latest \
  --host 0.0.0.0 --load-only en,ru --threads 1 --req-limit 30
```

Проверьте готовность: `curl http://127.0.0.1:5000/health`. Переводчик не требует API-ключа, а тексты остаются на сервере.

Содержание практических постов меняется в `DAY_TIPS` и `EVENING_EXPLAINERS` в `bot.py`. Расписание меняется в `SCHEDULE`. Страницы сайта находятся в `web/guides/`; для выкладки на сервер используйте `scripts/deploy-guides.sh`.
